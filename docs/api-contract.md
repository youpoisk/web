# API contract integration

The committed `contracts/openapi.json` mirrors the implemented backend contract. `contracts/source.json` pins its backend commit, normalized LF SHA-256 and generator version. Generated `src/shared/api/schema.d.ts` contains no runtime authentication or invented endpoints.

```powershell
pnpm api:import C:/repos/youpoisk-backend
pnpm api:check
pnpm api:check-source C:/repos/youpoisk-backend
pnpm build
```

Import requires a clean committed backend contract. Review its diff before committing the mirror/types. CI checks mirror integrity and generated-type drift; `api:check-source` also compares the current backend checkout and must run when changing either repository together. CI without a backend checkout validates the pinned contract, not an independently moving backend branch. The build runs the generated-type drift check.

Current coverage: register/login/refresh, current profile, device sessions/revoke/logout, current-password change, offline lease, per-video state/add, confirmed-channel personal rating and guest/authenticated video card lookup. Remaining library lists/search/hashtags, profiles/privacy, relationships, reviews/posts/feeds, DM, reports/admin/deletion, sync/import and trusted YouTube resolution are not yet advertised as working endpoints. Mail implementation is deferred by request.

UI mapping: auth/settings map to the implemented account/session operations; a video detail maps to by-youtube lookup and video state/add; channel rating requires a server-confirmed channel UUID. A client-provided UC and video association cannot grant that confirmation. Catalog, library/watchlist/ratings pages still need list/query APIs. Social/feed/chat/admin screens need their backend modules. Existing mock UI is not an API integration and must not be presented as live data.

Transport rules: expected_revision is a JSON field, change_seq is required nullable, unknown duration/average are null; never fabricate totals. Reject unsafe JavaScript integers. Access tokens stay in memory. Web credential types exclude JSON refresh tokens. The future first-party auth broker and browser checks are prerequisites for production auth; the type generator does not establish a browser session.
`import` verifies the exact file contents exist in the pinned Git commit. External $ref/$dynamicRef and schema $id rebinding are rejected before invoking the generator, preventing file/network schema resolution.
Standalone runtime validation: pnpm api:validators regenerates validators.js and declarations using pinned Ajv2020/ajv-formats/esbuild. Build/CI verifies byte-for-byte drift. Bundled helpers carry their MIT notices. Compilation happens only during development/build; runtime validation is tested with string code generation disabled, compatible with MV3 CSP. Tests cover route inventory and important credential/state/metadata/error/date constraints; generated library code is not claimed as handwritten 100% unit coverage. Clients must select web vs extension credential validators explicitly and reject unsafe numeric integers separately. These generated validators are preparation for the transport, not connected UI.
Business HTTP transport: src/shared/api/client.ts derives request/response types from operations; fixed HTTPS API origin (HTTP loopback for development), operation-only URLs and schema-validated path/query/header/body, 8KiB body and streaming256KiB response bound, timeout/abort, UTF8/JSON/schema and safe-integer checks. Browser fetch omits cookies and rejects redirects. Session provider stays in memory; recovering sessions never become implicit guests, owner+epoch changes discard late data/errors. Cookie-changing register/login/refresh are deliberately not this business transport and require the first-party broker. HTTP statuses/request ID/numeric Retry-After remain distinguishable without copying server messages, field values or credentials into errors. There is no automatic retry or auth recovery in this low-level layer; the later session coordinator must retry an immutable request at most once with the same key/body/lease. Generated code has conformance tests; handwritten client has enforced100% lines/functions coverage (branches reported separately). UI and extension do not use this transport yet.
The pinned mirror now includes19business operations plus2probes. Browser grant schemas/types are present for the future auth coordinator; issueBrowserCode/exchangeBrowserCode are excluded from ApiClient at compile time and rejected at runtime before fetch, including guest/recovering/authenticated scopes. Compile-only tests prove the exclusion and generated profile response shape; build runs them. These tests do not implement the coordinator or native API page. CI/local tooling requires the documented Node24.22.3/pnpm11.25.0 baseline.
