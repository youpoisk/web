# Logout and local data follow-up review: frontend 0270919, backend 80ac923

Frontend 0270919 "fix(web): per-account local data, bfcache reset and resilient logout". Backend 80ac923 "fix(auth): confirm broker logout unless it comes from the registered site". Both address docs/reviews/auth-fixes-followup.md (M1, L1-L6, N1).

Gate: PASS. M1, L1, L2, L5, L6 and N1 are fixed. L3 is fixed for the storage path but only partly for the crypto path. L4 (backend auth-e2e logout leg) was not in scope of these commits and stays open. No high or medium regression was found. The referrer check cannot be bypassed by web content as the site is built today. The anchor navigation works from async code. There is no reload loop. The new findings are low: a guest view can show the previous account's local data after a session expires, previous accounts' data is never removed unless they press «Выйти», and every login now costs an extra broker round trip.

## Regression checks

- Referrer check bypass: not possible for a foreign site as the site stands today. document.referrer is set by the browser from the document that started the navigation. A 30x chain keeps the original initiator's referrer (the foreign site). A meta refresh or JS redirect sets the redirecting page as referrer, so a bypass needs a document on the callback origin that navigates to an attacker-chosen URL. The site has none: navigation happens only through hash routes, fixed YouTube URLs with rel=noreferrer, and broker URLs that session.ts builds. User text (posts, reviews) is rendered as React text and is never turned into links. The extension pages on the same origin open only YouTube or option URLs, in new tabs with noreferrer. When a foreign page holds an opener reference and navigates our window, the foreign page is the initiator, so its own URL is the referrer. Framing: the broker page sends DENY, frame-ancestors 'none' and COOP, so the confirm button cannot be clickjacked. A framed copy of the site cannot reach the broker either, because the broker refuses to load in a frame. Condition to keep: if the callback origin ever hosts user-controlled HTML or an open redirect, the auto path becomes reachable. Note this in ADR-0008. A missing referrer (strict privacy settings, a different callback origin than the page origin) only adds one click.
- Anchor navigation: correct. A programmatic `click()` on an `<a>` without target navigates the same tab and needs no user activation. Popup blocking applies only to new windows. There is no opener and no new browsing context. History behaviour matches location.assign (a push entry). The anchor is appended to body, outside the React root, so React handlers do not intercept it. Login and register navigations now also send the site origin to /auth/authorize; that is harmless.
- Reload loop: none. The only reload trigger is `authenticated && user.id !== mockOwner` (main.tsx:17). An authenticated result always comes from completeCallback, which saves `owner = user.id` before returning (session.ts:141-150; a failed save throws, so the result is an error and not authenticated). On the next load the constructor reads that owner, so mockOwner equals user.id. If the cookie returns account Y, there is at most one more reload. If businessScope throws at init, mockOwner becomes 'guest'. That can happen only when the storage read fails right after a successful constructor read, and then boot fails too, so no authenticated view follows. The cost is L8.
- Guest and user data: the guest's `yp-guest-*` survives login and logout (it is device-local guest data). A user's data survives reloads and restores. It is removed on «Выйти» and on scope reset. Removal on the redirecting path runs in the `.then` after `a.click()`, before unload. If the user abandons the broker page, the local data is already gone (fail-safe). Another open tab of the same account can write `yp-X-*` keys again after logout (info). Legacy un-namespaced keys from older builds (`yp-ratings`, …) are orphaned and removed only by a scope reset (info; earlier builds wiped them on every load, so they are almost always empty).
- Logout without crypto: see L7. Missing global `crypto` makes construction fail (ReferenceError in main.tsx:8), so authSession is null and «Выйти» is not reachable. A throwing getRandomValues is the only path left, and the fallback does not cover it.

## New findings

L7. LOW. src/shared/auth/session.ts:176. The fallback calls `globalThis.crypto.getRandomValues`, which is the same object main.tsx:8 injects. In a browser, if the first call throws, the second throws too: logout() rejects, no broker navigation happens and the cookie family stays live (the case L3 was about). The state is unstored and gates only the notice, so it does not need to be random when the random source fails. Fix: `try { this.#crypto.getRandomValues(bytes) } catch { bytes.fill(0) /* notice will not match; logout continues */ }`, and do not write the nonce in that branch (any canonical 43-char value passes validLogoutQuery). Adjust the test to throw from both crypto objects.

L8. LOW (functional). main.tsx:12,17. On the callback load after a login from guest, mockOwner is 'guest' (the scope is committed only during boot). The fresh login therefore always triggers `location.reload()`. That drops the in-memory access token it just obtained and starts an automatic restore round trip through /auth/authorize. Every login costs two extra navigations. A transient failure on that second trip shows an error right after a successful login. Account switches do the same. Fix: do not tie the owner to module init. Keep `owner` in React state, render the data-holding tree with `key={owner}` (or move the useLocal calls into a child component keyed by owner), and when boot resolves with a different user, call setOwner(user.id) instead of reloading.

L9. LOW (privacy residual, same device). main.tsx:12,16,17. Only an authenticated mismatch is handled. When remembered account X's restore returns login_required (cookie expired, or revoked from another device), the scope is demoted to guest. The page still uses `yp-X-*`: the guest view shows X's ratings, reviews, posts and privacy choices, and guest actions write into X's namespace until the next reload. The same applies to the loading/redirecting render and to an error view. X's keys are also never removed unless X presses «Выйти». A later user of the device does not see them while signed in, but they stay in storage indefinitely. Fix: treat any final view whose owner differs from mockOwner as a mismatch (`(v.status==='authenticated'?v.user.id:'guest')!==mockOwner`; with L8's keyed tree this is one setOwner call). Call `removeMock(previousOwner)` when a restore demotes to guest, which matches the explicit-logout privacy boundary. Optionally render owner data only once the view is authenticated.

N2. Nit. backend authorize.html:24-27, broker.js:244-245. The confirm panel offers only «Выйти». L1 asked for a «Вернуться» link; today the user can only press browser Back. Add a link to redirect_uri without parameters (or call ui.cancel with a plain return). The decision is also not recorded in ADR-0008 (docs/adr/0008-browser-auth-protocol.md, logout paragraph).

N3. Nit. src/shared/auth/runtime.ts:115-116. signOut failures still map to "Не удалось завершить вход…". Give logout its own message, for example «Не удалось выйти. Попробуйте ещё раз.».
