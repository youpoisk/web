## Regression checks

- Forged `?logout=done` on the site: harmless. #captureLogout (session.ts:108-116) scrubs to origin+path first, then reads and deletes this tab's nonce. It reports logged_out only when logout=done, exactly one state, and state equal to the nonce. Any other value returns null, and boot continues as a plain load. A forged value can at most consume a pending nonce in the same tab, so the «Вы вышли» toast is lost. A URL that carries both `logout` and `code` drops the code. Forged `?error=` still needs this tab's pending 256-bit state (unchanged and tested).
- Logout ordering: correct. The bearer POST runs, then forgetLocal (clears mock data, guest scope with fresh epoch, cancels any pending flow), then the nonce is written, then the navigation. The nonce is per tab (sessionStorage survives the same-tab round trip) and single use (deleted on any `logout` return; a test asserts that a replay returns null). After a 204, main.tsx reloads; the scope is guest, so no restore runs.
- Account switch and epoch: correct (P3 above). A tab still bound to X sees the changed scope reference and fails closed with stale_session. No data crosses accounts.
- Damaged-scope reset: deletes only `yp.auth.scope.v1:*` keys. No other data is touched. It does not clear yp-* mock data of the unknown previous owner (L6).
- clearMock (main.tsx:5) deletes only keys that start with `yp-`. `yp.auth.*` keys (scope reference and per-tab pending/logout in sessionStorage) cannot match, because the character after "yp" is "." and not "-". When it runs, see M1.
- Settings are read-only, mock fixtures are emptied, and no password input remains (confirmed above).
- 4dbe496 scripts/qahash: `//go:build qatools`. The Dockerfile copies only cmd/, internal/ and api/ and builds only ./cmd/api, so the tool cannot enter a production image or a default `go build/vet/test ./...`. The gate mounts it read-only into the unit image with `--network none` and pipes SQL to the hard-coded local container youpoisk-yp040-db-1. Each statement is `UPDATE users … WHERE login_normalized='<listed>' AND status='active'`. Logins are regex-checked and the Argon2id hash is interpolated (no injection surface). Only the two listed QA rows are touched.

## New findings

M1. MEDIUM (functional, fail-safe) — main.tsx:5,7 (`clearPrivate: clearMock`) with session.ts:94-99 (start), 142-143 (commit), 153-154, 180-188. All local personal data is wiped on every page load for a signed-in user. Access lives only in memory, so every reload of a remembered account goes recovering → bootAuth → authorize('restore') → start() → clearPrivate. That deletes yp-ratings, yp-later, yp-reviews, yp-friends, yp-posts, yp-personal and yp-privacy before the broker round trip. The commit clears again even for a same-owner restore. Ratings, watchlist, reviews and so on therefore never survive a reload or a new tab. A guest's local list is also wiped on «Войти», which is probably intended. Not a security issue (it fails toward privacy), but it breaks the local features and the README claim. Fix: keep clearPrivate for in-memory caches only, or make it a no-op for mock data. Namespace mock keys by account (`yp-<userId>-ratings`) and delete them on logout (endAuth/forgetLocal path) and when a committed user differs from the previous owner. Alternatively store a `yp-owner` marker and clear only when the committed `me.id` differs from it. Add a browser check: rate a video, reload, and the rating stays.

L1. LOW — backend broker.js:229-238 (GET /auth/logout). Logout CSRF: any site can link to or redirect to `/auth/logout?redirect_uri=<registered callback>&state=<any 43 chars>`. The visit silently revokes the victim's cookie family and lands on the site; the forged state is ignored there, and the next boot's restore demotes to guest. Impact is forced logout only: no redirect beyond registered callbacks, no code or token issued, frame-ancestors 'none' and X-Frame-Options DENY block hidden-iframe use. The cost is a nuisance and denial of service; it also rotates and then kills the family. Acceptable as a documented risk for the MVP, but cheap to close. Recommendation: auto-revoke only when the navigation clearly comes from the site, meaning the Referer origin equals the redirect_uri origin (the site's default strict-origin-when-cross-origin sends it) and Sec-Fetch-Site is not none. Otherwise show a one-click «Выйти из YouPoisk?» confirmation with a «Вернуться» link. Never refuse outright, because privacy settings may strip Referer. Record the decision in ADR-0008.

L2. LOW — main.tsx:12 (authBusy). After signIn or signOut returns 'redirecting', authBusy stays true. If the user presses Back from the broker and the browser restores the site from bfcache (the site has no unload handler and is not no-store), the page comes back with authBusy=true. «Войти» and «Выйти» then do nothing silently, and bootAuth does not re-run, so the abandoned pending flow is not cancelled either. Fix: on `pageshow` with `event.persisted`, reset authBusy and re-run the boot logic, or simply reload.

L3. LOW — session.ts:168-176. Two failure paths skip the cookie logout. If forgetLocal throws (storage read fault, stale_session) or the nonce cannot be written (crypto or storage), logout() throws. No broker navigation happens, so the cookie family stays live. The user sees the generic "Не удалось завершить вход" message (runtime.ts:113-115). The nonce only gates the toast. Fix: when forgetLocal or the nonce save fails, still return the broker URL (with a fresh state that is simply not stored); the return then just shows no message. Give logout failures their own message.

L4. LOW — backend scripts/auth-e2e.mjs:73-76. The logout-page checks cover only render and the 400 for a foreign callback. Add an HTTP emulation of what the page does: drop the bearer, then hint → refresh (attempt) → POST /v1/auth/logout with the fresh bearer → refresh with the old cookie gives 401. Also check that an extra key or a malformed state on /auth/logout gives 400. This pins down P1 end to end.

L5. LOW — main.tsx:27,33. Fictitious social content is still shown to real accounts: the «Обсуждают друзья» rail with an invented friend quote, and the four invented people on /friends and /subscriptions with friend and follow actions. Remove them, or label them as examples, until the relationships API exists.

L6. LOW — main.tsx:7. The damaged-scope reset does not clear yp-* mock data. The previous owner is unknown after the reset, so a guest can see the previous account's local reviews or lists. Call clearMock in the reset branch, or this is solved by M1's per-account keys.

N1. Nit — runtime.ts:44-49. startupFailure maps a storage-blocked DOMException (no `kind`) to the generic exchange message. Treat a non-kinded constructor error as storage (the only constructor dependency that throws without a kind).

Info — broker.js:125-131: in logout mode, a 409 refresh_advanced returns null and the page reports logout=done without revoking. The consumed cookie can no longer refresh: its next use counts as reuse and revokes the family. The child token belongs to whichever holder advanced it, normally the same browser jar. Acceptable; worth one sentence in local-development.md. Duplicating a tab copies sessionStorage, so a duplicated tab can hold a copy of an in-flight pending flow; only one copy can complete, and the other shows an error. Acceptable.
